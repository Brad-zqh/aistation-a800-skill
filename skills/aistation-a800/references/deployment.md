# 部署、镜像和正式任务

先看当前平台界面或现有平台 API 的真实字段。AIStation 版本、队列、镜像仓库和端口映射随学校配置变化；不要从这个参考文档猜一个创建任务 API。若没有可用浏览器能力，先完成本地代码/配置/镜像清单准备，再向用户索取真正缺少的接入信息。

## 从临时开发转入正式计算

1. 确认当前任务授权范围、GPU/CPU/内存、队列、持久共享目录和任务生命周期。一次已执行案例使用 A80080GB、CPU4/64GB，但这些不是所有任务的默认配额。
2. 把代码、权重、独立环境、冻结配置放项目的持久目录。临时容器磁盘和端口不保证保存；模型镜像保存100%成功也不代表模型计算成功。
3. 优先复用已验证的项目环境。原案例镜像内 Python3.8/CUDA11.4 可运行固定 llama.cpp；不能因此断言支持最新 Transformers/VLM。新库需要不同 ABI 时，建立新前缀/镜像，不能升级活跃任务依赖。
4. 校验上传文件大小及完整 SHA256。记录模型 revision/量化、二进制及依赖库 bundle SHA、服务代码和环境版本。GGUF 权重与基础镜像分别登记。
5. 在实际 GPU/容器内检查 `nvidia-smi`、cgroup、项目 Python、CUDA可用性，并用少量非敏感合成输入测试真实 GPU 运算与新进程重启。公开基准或合成案例不是研究数据的准确率。
6. 保存镜像后核实际传输成功；提交正式任务时核共享目录挂载、启动入口、资源、超时/回收规则。原案例从临时开发实例切到正式任务才解除开发实例的两小时限制；不能将这个历史规则套在别的平台。
7. 等正式容器真正运行后，重新获取它的 SSH 映射及已认证主机公钥，重做只读核查、运行哈希和合成测试。释放不再使用的本任务开发实例，不复用其旧端口。若正式任务仍依赖开发实例，先完成迁移。

## 服务形态

长任务入口放持久脚本，由平台主进程/监督器管理。不要依赖交互 SSH 窗口、聊天是否 idle 或一次临时 notebook cell。监督器分别记录阶段、PID、创建时间、exit code和独立模型服务状态；终端日志只含安全运维元数据。

llama.cpp 必须依据当前二进制 `--help` 选择参数，不能混用不同版本支持的标志。原已执行案例冻结过 b11723、CUDA架构80、单槽、8192上下文、无连续批处理和 prompt 缓存。这些是某个标注器的规格，不是新任务必须用的通用性能参数。原任务不静默改参数；新任务根据显存和复现测试另登记。

镜像下载/内网源失败时记录 HTTP/网络错误类型；一次502不表示整个实验失败，也不应通过全局关闭 TLS 检查解决。能复用可信已安装环境时明确记录恢复来源，不冒称成功在线重建。
