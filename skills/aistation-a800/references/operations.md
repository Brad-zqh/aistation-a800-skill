# 身份、隧道、监测和恢复

## 私有 profile

复制 profile.example.json 到仓库外的私有路径，再填平台上当前任务的实际配置。只写密钥的路径，不写密钥内容或密码。此机器的默认私有位置为 `E:/CodexData/private/aistation-a800/current.local.json`，可用环境变量 `AISTATION_A800_PROFILE` 覆盖。安装 skill 不会把 profile 上传 GitHub。

原研究项目已有具体 worker、隧道、冻结计划和只读监测器时，先用它们；通用助手不能替代项目自己的成员/证据/模型QA。

## SSH 隧道

核对 `ssh.exe`、任务 key、known_hosts 当前文件，以及平台端口映射。已有隧道必须同时核 PID、创建时间、完整可执行文件与转发参数，不能只按进程名认领。复用现存正确隧道。

需要新隧道时，从 profile 构造 argv，使用 `-N -L 127.0.0.1:本地端口:127.0.0.1:服务端口`，以及 `IdentitiesOnly=yes`、`BatchMode=yes`、`StrictHostKeyChecking=yes`、指定 `UserKnownHostsFile`、`ExitOnForwardFailure=yes`、keepalive。Windows 后台进程隐藏窗口，stderr在RAM中检查或只留安全错误码，不能持久记录正文/口令。不要把真实用户名、内网地址、认证文件打包进公共 skill。

记录实际 argv/PID/创建时间到本机项目运维记录。新隧道成功后核一个不返回正文的健康/状态入口，以及服务公开的模型/运行 bundle/服务代码哈希。不要对已完成并正常关闭的服务持续HTTP探活。

## 监测顺序

- 先看真实完成收据和QA，识别已经正常退出的模型/client。
- 刷新活任务进程创建时间、exe、完整脚本/模型参数；平台“失败”或“运行中”需要与容器事件、服务状态和有效检查点交叉核实。
- 按流式完整行核进度、有效记录、重复ID和队列成员。活跃追加的末尾半行先忽略，不截断；同一条记录的重复推理不是新样本。
- 同时看GPU利用率/已加载模型占用、cgroup memory.max/current与CPU限额、磁盘、state时效。首次源扫描、长文本或读取大文件可暂不增长，不直接称停滞。
- 收据中的源/提示/权重/运行哈希应与当前定义一致。新模型、不同后端或量化不能当作旧结果逐位复刻。

## 出错如何继续

先区分监测器错误、SSH传输、模型服务、客户端实现和研究门槛失败。只报告安全类型与代码位置。传输短断时，已有带重试的活客户端不应被重启。隧道真正退出才恢复相同已验证主机连接。

代码实现错误可在既有授权定义内修复：保留旧完整检查点，登记修前/修后SHA、具体差异和回放；不静默改变提示、量尺或样本。研究门槛未过按事前失败规则保留有界结果，不通过改标签或删验证样本追求性能。

停止或释放前核目标属于本任务，使用平台确认的 task ID/对应进程身份。禁止宽泛 `killall`、按名称批量结束模型进程、清空共享目录或抢占其他任务。
